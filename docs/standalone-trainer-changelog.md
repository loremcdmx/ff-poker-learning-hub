# Changelog standalone-тренажёров

Документ ведёт историю правок по standalone Learning Hub тренажёрам:

- `rfi-open-position-lesson` — open-raise по позициям;
- `sb-unopened-lesson` — игра SB без опена до Hero;
- `bb-call-defense-lesson` — защита BB коллом;
- `vs-one-raiser-positions-lesson` — игра против одного рейзера в свободных позициях;
- `vs-one-raiser-sb-lesson` — игра SB против одного рейзера;
- `resteal-lesson` — рестил;
- `flop-cbet-hu-lesson` — c-bet HU;
- `flop-checkraise-lesson` — check-raise флопа;
- `vs-3bet-defense-lesson` — защита против 3-бета;
- `poker-simulator` — общие практические и embedded-сценарии, которые используют уроки.

Статусы:

- `Released` — изменение входит в production-историю за 2026-07-17—2026-07-26.
- `Context` — восстановлено по QA-потоку и локальным заметкам; перед релизом проверять по фактическому diff.
- `Blocked` — код и проверяемые данные подготовлены, но публикационный гейт
  сознательно не пройден; изменение не выпускалось.

## 2026-07-26 — релиз исправлений аудита и достоверных данных

Статус: `Released`.

- `rfi-open-position-lesson` больше не публикует частичный или смоделированный
  каталог. Наблюдаемая игра поля собрана в 30 полных состояниях:
  5 стеков × 6 позиций, 4 когорты и 169/169 рук в каждом чарте. Минимальный
  знаменатель — 55 при жёстком пороге 50. Бакет `<15 BB` — точная сумма пяти
  исходных непересекающихся диапазонов до расчёта процентов; сглаживания,
  соседней подстановки и скрытых disabled-состояний нет.
- RFI-источник закрыт по реальным execution receipts и SHA-256:
  36 504 исходные строки, 65 334 010 известных карт из 74 722 772 допустимых
  возможностей (`87,435206%`). Отдельный CoinPoker/PartyPoker supplement
  добавляет 5 108 точных возможностей из восьми исполненных immutable-shard;
  пустые шарды остаются в provenance как доказанные нули.
- Release-data gate проверяет не только наличие payload, но и membership,
  уникальных игроков, закрытое временное окно, source-specific SQL,
  recovery-validation, целочисленную агрегацию и privacy boundary. Все шесть
  обязательных поверхностей проходят `READY`.
- `bb-call-defense-lesson` явно отделяет доказанные клетки 15 PNG от
  недоказанного предположения, что сайзинги `2 / 2,5 / 3 BB` были сыграны в
  одинаковых турнирных условиях.
- `vs-one-raiser-positions-lesson` не называет глубокие матрицы
  short-stack-данными: при отсутствии точного среза `18–22 BB` показывает
  честное состояние «нет данных». Невозможные позиционные сочетания не
  рисуются.
- `vs-one-raiser-sb-lesson` подаёт `−6,2 BB/100` как наблюдаемую связь, а не
  доказанную причинность, и показывает диапазон чувствительности
  `5,0–9,8 BB/100`.
- `resteal-lesson` не смешивает точный профиль `BB против BTN · open 2 BB` с
  банками после `2,2–3 BB`; расширенные размеры остаются только учебной
  настройкой.
- `flop-checkraise-lesson` сохраняет 240 BB во всех узлах раздачи, использует
  явно заданные диапазоны оппонента и авторские русские подписи вместо
  regex-перевода. Полевые частоты прямо названы сыгранными решениями, а не
  solver-чартом.
- `vs-3bet-defense-lesson` не подменяет выбранный сайзинг соседним полевым
  бакетом: полная таблица появляется только для опубликованного контекста,
  иначе интерфейс честно сообщает об отсутствии среза.
- Static `poker-simulator` не штурмует отсутствующий backend: `404/405`
  завершают синхронизацию, очередь ограничена, локальные рейтинг и история
  продолжают работать.
- Changelog, данные, JS/CSS и HTML связаны актуальными immutable cache-token;
  релизные проверки запускаются уже на изолированном кандидате.

## 2026-07-26 — завершение починки аудитов уроков 01–10

Статус: `Context` — промежуточное состояние до релиза выше.

- В `rfi-open-position-lesson` обычный quality-check теперь отдельно доказывает
  безопасное заблокированное состояние: из `36` обязательных
  `стек × позиция` срезов готовы `28`, а восемь конкретных коротких поздних

  остаётся красным до появления достаточного первичного источника. Coin/Party
  pipeline также отвергает старый private parser-validation fingerprint после
  изменения SQL-шаблона: обычный тест доказывает fail-close, но не выдаёт
  устаревшую верификацию за право собрать новый publication merge.
- В `bb-call-defense-lesson` рядом с выбором сайзинга явно записана граница
  первоисточника: 15 PNG подтверждают клетки своих матриц, но не доказывают,
  что у размеров `2 / 2,5 / 3 BB` совпадали стек, анте и турнирный контекст.
  Урок больше не предлагает объяснять разницу между матрицами только
  пот-оддсами.
- В `vs-one-raiser-sb-lesson` точка `−6,2 BB/100` больше не подаётся как
  доказанный эффект лишних коллов. Экран показывает её как описательную связь
  текущего окна и рядом даёт фактический диапазон чувствительности
  `5,0–9,8 BB/100` по допустимым срезам.
- В `flop-checkraise-lesson` удалён regex-перевод learner-текста. Названия
  структур доски, действий, бэкдоров, гатшотов и шоудаун-вэлью теперь
  записаны авторским русским текстом в данных, HTML, общем renderer и
  procedural feedback; контракт запрещает возврат смешанных
  английско-русских подписей и старого написания «велью».
- В `vs-3bet-defense-lesson` поле больше не подставляет чужой бакет размера

  полная таблица появляется только для разрешённого
  `BTN · IP · 80+ BB · все размеры`.
- В static-версии `poker-simulator` рейтинг, архив и синхронизация раздач не
  обращаются к отсутствующему backend. Ответы `404/405` завершают синхронизацию
  как terminal, очередь имеет пределы по размеру и попыткам, а локальная
  история продолжает сохраняться.
- Обновлены immutable cache-token затронутых CSS/JS/data-файлов и тесты,
  которые связывают HTML с фактическими байтами ассетов.
- Этот промежуточный blocked-срез заменён релизом выше.

## 2026-07-26 — честная практика и сравнение когорт в уроке «SB без опена до тебя»

Статус: `Blocked`.

- Практический стол показывает репрезентативный стек внутри каждого бакета:
  `6–8 BB` и `<6 BB` больше не превращаются в одинаковые `6 BB`. Общий банк
  по-прежнему включает около `1 BB` анте, но эта сумма честно названа анте
  стола и распределяется между всеми семью местами, а не приписывается BB.
- Кнопка обычного рейза больше не обещает неподтверждённые данными `3 BB`.
  В категорическую практику допускаются только руки с `N≥50` в обеих
  сравниваемых когортах; действие с частотой от `30%` принимается как
  допустимый микс и не считается ошибкой.
- Сравнение больше не трактует любой перевес первой лиги как ошибку нижней
  группы. Если ранги 15–18 чаще выбирают ту же основную линию, разбор прямо
  говорит, что различие между группами находится не в этой кнопке.
- На экране сравнения теперь видны все три загруженные когорты, включая
  `2–3 лиги · ранги 6–14`. Короткая подпись источника уточняет, что лига
  определяется по рангу в момент раздачи.
- Третья карточка главного экрана следует выбранному стеку, русское склонение
  числа комбинаций исправлено, а прогресс обновляется после каждой попытки
  начиная с 25-й.
- На мобильной ширине матрица сохраняет читаемые клетки и прокручивается
  внутри карточки без горизонтального переполнения страницы.
- Коммит, публикация и production-проверка не выполнялись: изменения остаются
  в локальном WIP до прохождения релизных гейтов.

- В `sb-unopened`, `vs-one-raiser-positions` и `vs-one-raiser-sb` один
  контракт связывает мудрости, сравнения, hand-level действия и EV; частичный

- Benchmark action cube и EV пересобраны за единое окно
  `2023-09-01…2026-07-22` с одним rank-at-hand bridge. Action-источник собран
  из 14 непрерывных time-shard: 287 846 additive-строк,
  182 797 437 возможностей и `other=0`; долгий квартальный шард заменён тремя
  точными месячными окнами без разрыва или пересечения. EV собран из 12
  непрерывных time-shard и 218 481 возможности.
- Три урока перешли из `methodology_only` в `READY`: контекстный каталог
  содержит 177 полностью рабочих сценариев для первой лиги, 2–3 лиг и рангов
  15–18. Это 531 cohort-чарт, 89 739 hand-клеток и 167 059 890 опубликованных
  возможностей. Все обычные клетки проходят `N >= 50`; единственное явно
  ограниченное near-floor исключение — четыре руки `N=48–49` в
  `SB без опена · <6 BB · первая лига`, необходимом коротком учебном якоре.
  Мёртвых и disabled selector-state в интерфейсе нет.
- Fail-closed fallback больше не резервирует высоту несуществующего стола и
  action dock: три урока помещаются в desktop-viewport, а на мобильном
  складываются в одну колонку без обрезания контейнеров. Пустые rule-callout и
  подписи proof-card не создаются, если у принципа нет отдельного правила.
- Runtime, генератор страниц и `check:release-data` теперь используют один
  строгий readiness-контракт. Он требует точное окно, непрерывный provenance,
  обязательные учебные якоря по глубинам, три когорты и `169/169` рук с
  обычным порогом `N >= 50` в каждом включённом чарте. Исключение `<6 BB`
  ограничено точным спотом, когортой и максимум четырьмя near-floor руками;
  пятая слабая рука или тот же `N` в соседнем стеке блокируют сборку. Любая
  отсутствующая когорта или `168/169` рук также блокирует observed-экраны.
- Каждый готовый benchmark-payload связывается SHA-256 с точным provenance и
  hand-level action counts. Runtime заново сверяет digest, знаменатели,
  агрегаты и отображаемые проценты; проценты, которые разошлись с исходными
  счётчиками хотя бы в одной клетке, не могут открыть чарты или практику.
- Browser-payload хранит каждое наблюдение один раз: `169 × 4` целых
  action-counts на срез. Проценты, знаменатели и клетки чарта выводятся из этих
  счётчиков лениво только для открытого спота; manifest отдельно связывает
  полный источник и точную publishable-матрицу, поэтому отфильтрованные слабые
  хвосты нельзя незаметно вернуть в интерфейс.
- Action cube и EV используют один byte-identical rank-at-hand bridge рангов
  `1–18`, связанный с отдельным canonical SQL. Публикуемые шарды делятся только
  по непересекающимся окнам времени и каждый сохраняет всех пользователей
  bridge; прежний user-modulo режим, способный тихо потерять часть поля,
  теперь завершается ошибкой.
- Для ключевого `SB против BTN · 2x · 18–25 BB` EV и action-чарты используют
  одно окно и один rank bridge: первая лига показывает `+1,56 BB/100`, ранги
  15–18 — `−4,61 BB/100`, разрыв составляет `6,17 BB/100`. Контракт не даёт
  снова смешать этот outcome с action-частотами другого окна.
- Классификатор короткого стека считает пушем и прямой all-in, и
  рейз, который покрывает effective stack; граничный контракт не даёт
  вернуть ошибку `3 BB all-in → обычный рейз`.
- Вместо наложения двух палитр в одной клетке сравнение диапазонов
  показывает две целые матрицы; глубина стола, ставки и action dock
  приведены к геометрии остальных тренажёров.
- Служебное значение сайзинга `other` переводится во всех контекстах как
  `Другой сайзинг`, а правило про разделение SB-диапазона больше не утверждает,
  что комплит остаётся широкой серединой в стеке, где уже доминирует пуш.
- Банк до решения Hero считается одной исполняемой моделью: блайнды + BB ante +
  опен. Поэтому unopened-спот показывает `2,5 BB`, а один опен `2x` — `4,5 BB`,
  включая ante ровно один раз.
- Селекторы чартов больше не показывают невозможные или неполные сочетания:
  каждый следующий ряд строится из полного контекстного каталога, а каждая
  видимая кнопка открывает `169/169` рук во всех сравниваемых когортах.
  Disabled data-кнопок и тупиков с автоматической подменой соседнего спота нет.
- Мудрость короткого стека больше не выдумывает недобор пушей там, где две
  группы дают одинаковую частоту: при разнице меньше 2 п.п. она прямо
  переключает внимание на устройство колла и обычного 3-бета.

- В обзоре по позициям показываются попадания/ошибки по позициям; hover/детализация показывает лишние opens и пропущенные opens разными цветами.
- Вкладка `Чарты` очищается до стеков `15+ BB`; короткие push/fold-секции убраны из основной рекомендации, чтобы не перегружать справочник.
- Вкладка `Как играют реги` остаётся для наблюдаемой игры поля и коротких стеков; селекторы стеков увеличены, матрицы осветлены.
- Добавлена таблица fold equity и частоты получить 3-бет по количеству игроков за спиной, от 6 до 1 игрока.
- Для статистики по FE выставлена глубина `30 BB+` и проверка, что open-push не просачивается в сэмпл.

### Защита BB коллом

- Порядок вкладок приводится к продуктовой логике: `Видео` до данных, `Чарты` до `Данных`, практика в конце.
- Переписан главный посыл: цель — довести решения защиты BB до автоматизма, а не просто “коллить”.
- На главной странице подчёркнуто:
  - BB замыкает экшн;
  - за один блайнд можно гарантированно увидеть флоп;
  - это не heads-up стол, а полный стол с уже завершённым экшеном до BB.
- Целевые показатели защиты показывают `пас` как главный риск-метрик: если фолд слишком высокий, оппонентам выгодно душить открывающего через 3-беты.
- В data-вкладку добавлены срезы по глубинам `70 BB+`, `40–70 BB`, `0–40 BB`.
- Для multiway добавлено объяснение, почему широко заходить хуже: pot odds лучше, но equity и реализация equity страдают из-за sandwich-позиции и сильного range коллера.
- Для третьей лиги добавлены/уточнены блоки equity realization: показывается разница equity и реализуемого equity по типам рук, со сноской про коэффициент реализации.
- Практика визуально подравнивается под open-raise: те же крупные кнопки, похожая панель результата, одинаковая геометрия стола и ответа.

### Рестил

- Rank-at-hand payload рестила пересобран за окно
  `2023-09-01…2026-07-22` по шести непрерывным time-shard с latest-first
  выбором до poker-фильтров: 5 520 018 возможностей, `other=0`, 12 240 строк
  в additive cube. Query/job/result SHA каждого шарда связаны с manifest, а
  приватные SQL, CSV и failed-attempt evidence не попадают в browser payload.
- Runtime показывает 10 готовых сценариев вместо декартового набора из
  частичных фильтров: `CO/BTN` × `2x · 25–30`, `2x · 30–35`,
  `2x · 35–40`, `2x · 25–40` и `2.5–3x · 25–40`. Во всех четырёх когортах
  каждый сценарий имеет `169/169` рук с `N >= 50`; `2.5–3x` собран точным
  сложением исходных `2.5x` и `3x` до расчёта процентов. Disabled и пустых
  data-состояний нет. В базовом
  `BB против BTN 2 BB · 25–40 BB` стандартизированная частота прямого пуша
  растёт от 3,203% у рангов 15–18 до 11,155% в первой лиге.
- Отдельная classifier-регрессия защищает границу между обычным 3-бетом и
  прямым пушем: в exact-срезе первой лиги `BTN 2 BB · 30–35 BB` AA даёт
  674 обычных 3-бета против 6 пушей, а 88 — 93 против 483. Поэтому частый пуш
  88 около 30 BB подтверждён полем и не является ошибкой распознавания
  обычного сайзинга.
- Runtime больше не подменяет точный `BB против BTN 2 BB` пулом более
  широких ситуаций; contract исполняет реальный browser bundle и
  доказывает, что exact slice не смешивается с другим пулом.
- Математическая матрица явно отмечает выход на границу модели: если при
  выбранных допущениях EV-фильтр пропускает почти любые две карты, урок
  называет это стресс-тестом, а не наблюдаемой частотой поля, точным чартом
  или советом пушить весь диапазон.
- Вкладка `Подробнее` переименована в `Математика рестила`.
- Данные про рост restil-push по лигам вынесены в отдельную вкладку и оформляются как наблюдаемая игра поля, не как рекомендация.
- Возвращается сравнение EV, потому что главный урок рестила — не частота сама по себе, а то, что spot может быть на блайнд плюсовее в chipEV.
- Добавлена вкладка `Реакция на рестилы`: как поле отвечает на restil в разных стексайзах, позициях и сайзах open.
- В `Реакция на рестилы` исправляется фильтр, чтобы не смешивать squeeze-push и reraise-over поверх restil.
- Continuation chart нормируется по возможностям открытия конкретной руки: если AA открывается почти всегда, а 55 открывается реже, цвет показывает долю продолжений относительно открытий этой руки, а не сырой абсолютный счёт.
- Сравниваемая группа новичков в данных и интерфейсе единообразно определена
  как `Ранги 15–18`, без подмены более широкой novice-группой.
- Градиенты в матрицах restil/rank comparison осветляются и приводятся к общему стилю, чтобы процент и hand label читались.
- Практика переводится на три крупные кнопки `пас / колл / рестил` в едином визуальном стиле.

### C-bet HU

- Полевые частоты c-bet включены из полного exact full-history cube:
  четыре непересекающиеся когорты, `BTN/CO/HJ/MP/EP` и пять стеков образуют
  полный каталог из 100 рабочих срезов. Каждый срез проходит `N >= 50`
  (минимум 10 603), поэтому фильтры не ведут к серым, скрытым или
  подставленным значениям; методический атлас, алгоритм и практика остаются
  отдельным учебным слоем.
- Практика переводится с simulator-like управления на учебный режим:
  - ограниченное число крупных кнопок;
  - счётчик правильных и ошибок;
  - понятный feedback после ответа;
  - удобная кнопка следующей ситуации рядом с action area, без необходимости скроллить.
- Исправляется обрезание action-кнопок снизу.
- Фиш/рег профиль выделяется не только текстом, но и цветом/стилем бокса, чтобы сразу было понятно, против кого играем.
- Больший сайз с хорошей рукой трактуется мягче: это может быть разумный exploit, но в feedback добавляется предупреждение, что компетентные оппоненты могут читать сайзинг.
- Низкая связанная доска теперь даёт один и тот же урок в примерах, алгоритме
  и практике: с чистым воздухом базовая линия — чек; ставка 25% допустима
  только при понятной причине, а не как автоматический c-bet.
- Когорты c-bet больше не пересекаются: все агрегаты, фильтры и мудрости
  используют один набор `R1–5 / R6–10 / R11–14 / R15–18`; методический
  маленький сайз во всех блоках приведён к диапазону `25–33%`.

### Check-raise флопа

- Полевые матрицы check-raise включены из того же exact full-history cube:
  четыре непересекающиеся когорты, опенеры `CO/BTN` и четыре стека дают
  полный каталог из 32 рабочих срезов. Во всех строках сходится знаменатель
  `fold + call + raise`, `other=0`, минимальный `N=75 257`; серых и
  недоступных data-состояний нет. Учебные board/hand-карточки и практика
  остаются методическим слоем и не выдаются за hand-level observed-данные.
- Практика стала бесконечной: ситуации генерируются процедурно, а не заканчиваются ограниченным паком.
- Добавлен тумблер `Только флоп / Полная раздача`.
- Feedback разделён на базовые категории:
  - check-raise OK;
  - loose check-raise;
  - очевидно пропущенный check-raise;
  - call как допустимое решение для средних рук.
- Уточнены грейдеры по спорным рукам:
  - `AK` на `T62` против крупного сайза — минимум call;
  - suited связки с equity не должны автоматически уходить в fold;
  - `KQ` на `J72` может рейзиться из-за блокеров `KK/QQ/KJ/QJ`, equity и backdoors.
- Для full-hand режима отмечен открытый класс проблем: postflop continuation не должен чекать behind там, где aggressor очевидно продолжает ставить turn/river.
- Вкладка `Главное` очищена от технических аннотаций и лишних summary-блоков.
- Добавлен K92r value/mix блок:
  - board показывается картами;
  - сильное value: `K9`, `K2`, `92s`, `22`, `99`;
  - сильные Kx миксуются: `KQ`, `KJ`, `KT`;
  - объясняется, что `Q/J/T` блокируют часть broadway-barrel рук соперника.
- Убран дубль value-списка слева, если та же информация уже показана на карточках справа.
- На K92r снова видны заголовок, обе группы и все восемь hand-labels
  (`K9`, `K2`, `92s`, `22`, `99`, `KQ`, `KJ`, `KT`); мобильная сетка
  перестраивается без клиппинга.
- Фолд соперника завершает раздачу без шоудауна: будущий ранаут и закрытые
  карты соперника не раскрываются, terminal copy и общий completion-баннер
  явно говорят, что рука закончилась без вскрытия.
- В data-таблицах переименовано `c-bet` в смысл `нам ставят`: это частота, с которой CO/BTN ставит в BB после нашего check.
- Таблицы по структурам флопа поджаты: убраны raw sample counts, добавлены визуальные разделители двойных столбцов по лигам.
- Карточки отдельных раздач на вкладке `Примеры` остаются методическими:
  общий готовый cube агрегирован по позиции и стеку и не выдаётся за
  board-level hand evidence; выдуманных полевых процентов на карточках нет.

### Защита против 3-бета

- VS3 field payload прошёл контракт effective-shove, полного окна,
  latest-first и связанного provenance. Наблюдаемый field view включён только
  для точного `BTN · IP · 80+ BB · все сайзы`, где четыре когорты имеют
  `169/169 × N >= 50`; неполные срезы не становятся disabled data-кнопками.
- В target-чартах и практике невозможные relation/position варианты
  исключаются из контекстного каталога: BTN не предлагает OOP, SB не предлагает
  IP; на desktop и mobile остаётся 169 рук и ноль disabled/aria-disabled
  data-селекторов.
- Вкладки `Чарты` и `Как играют реги` объединяются в один более плотный справочник: слева наша стратегия, справа поле с теми же фильтрами.
- `Пас` становится основным показателем на таблицах, потому что overfold — главный источник того, что нас выгодно 3-бетить.
- На `Главное` выносится целевая логика по позициям:
  - сколько фолдить;
  - сколько коллить;
  - сколько 4-бетить;
  - сколько пушить;
  - почему это выгодно;
  - где проходит граница, после которой оппонентам становится слишком прибыльно давить.
- В matrix explorer добавлен вес открытия руки: если рука почти не открывается в исходном range, цветовая заливка показывается только нижней частью клетки, а не как полноценная частота.
- Добавлен компактный блок сравнения “наша стратегия и поле” по одной руке с одинаковыми фильтрами.
- Перегруженная инфографика по слоям заменяется более читаемой таблицей/карточкой: вместо одинаковых bar widgets показываются различия по действиям и открываемость руки.
- Раздел частых ошибок объясняется проще: “здесь видно, как стратегия начинающих игроков отличается от топов”.
- Из раздела убираются лишние технические заголовки и context chips, если фильтры уже видны на экране.
- Матрица ошибок должна показывать частые hand-level отклонения поля от целевой стратегии: где поле лишне защищается и где недозащищается.

### Симулятор и общий стол уроков

- В static production нет бесконечных повторов на несуществующие API:
  hand sync и trainer events переходят в конечное local-only / not-configured
  состояние; outbox/archive имеют лимиты по штукам, байтам и попыткам.
- Online lobby скрыт по умолчанию и появляется только при явном
  feature flag и успешной JSON health-проверке `/api/rooms`.
- Snapshot-модель отдельно учитывает BB ante и блайнд: ante не раздувает
  видимую ставку, BB-call не списывает блайнд дважды, а сумма стеков
  и банка сохраняется.
- Неделя и сезон считают руки из одного набора реально отрисованных
  раздач; график, счётчики и `Твой результат` одинаково уважают фильтр
  размера стола и показывают явное пустое состояние вместо чужого среза.
- В MTT-режиме `Разбор` следующая рука сохраняет состав и фактические стеки
  предыдущего стола вместе с растущим номером турнира; полный сброс остаётся
  только для bust/reset, а не для учебного темпа.

`npm run check:release-data` в составе `npm run check:release`.

## Открытые UX/functional риски

- Embedded/full-hand practice всё ещё зависит от единого simulator timeline barrier. Если тренажёр обходит общий simulator runtime, могут возвращаться:
  - раннее открытие флопа до окончания preflop action animation;
  - разные версии betbox;
  - fallback-позиционирование карт оппонентов.
- Для всех practice routes нужно сохранять единый action dock:
  - три большие кнопки для учебного решения;
  - next situation рядом с action area;
  - feedback без обязательного скролла.
- Для всех chart/data routes нужно поддерживать один стиль:
  - общий chart-system;
  - action colors consistent;
  - compact labels;
  - no raw SQL/provenance/N-heavy panels в основном UX;
  - каждый обязательный learner-facing срез собирается из exact-source до
    выпуска; нехватка данных красит release gate, а не создаёт скрытый,
    disabled или подменённый контрол.
